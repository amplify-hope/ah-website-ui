# Consolidate `ah-website-api` into `ah-website-ui`

Jira Epic: [WEB-20](https://amplifyhope.atlassian.net/browse/WEB-20)

## Goal

Consolidate the `ah-website-api` Express microservice into the `ah-website-ui` Next.js 15 app so the donation platform is a single, unified codebase and deployment. Driven by one engineer finding the microservice split slows development more than it helps.

## Decision Log

| Decision                           | Choice                                                                                                                                                   | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Consolidation direction            | Port Express controllers into Next.js Route Handlers inside `ah-website-ui`                                                                              | Single deployable, single repo, no cross-service network hop                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `stripe_products` Postgres table   | Drop entirely — no database at all post-migration                                                                                                        | Table is write-only today (webhook upserts, nothing reads it); dropping it removes RDS hosting, `pg`/connection pooling, and an entire failure mode                                                                                                                                                                                                                                                                                                                                                                                                        |
| Cutover strategy                   | Big-bang — build the full replacement, verify, then switch over once                                                                                     | Small surface (8 routes, no DB reads to reconcile) makes an incremental strangler pattern pure coordination overhead for a solo engineer                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Auth/session scope                 | Preserve exact current behavior: JWT-verified magic link → redirect straight to a Stripe-hosted Billing Portal session. No new app-level session/cookie. | Avoids scope creep into a new "logged in" experience; this migration is about consolidation, not new features                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `services/donations.ts` (frontend) | Delete — it calls `/donations` and `/donations/:userId`, which do not exist anywhere in `ah-website-api`                                                 | Dead/aspirational code with zero callers found in the app                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Testing rigor for new routes       | Add route-level integration tests for every new Route Handler, in addition to existing unit-test conventions                                             | The donation and sign-in routes are the risky part of the port and had no route-level coverage                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Hosting platform                   | AWS Amplify Hosting (replacing per-app EC2 + Docker + nginx + certbot)                                                                                   | Nonprofit AWS credits only offset AWS spend; traffic is low so a platform with near-zero idle cost and zero server/container ops fits best. Amplify has first-class Next.js App Router Route Handler support                                                                                                                                                                                                                                                                                                                                               |
| CI/CD                              | Move build+deploy into Amplify's own git-triggered pipeline (`amplify.yml`); GitLab CI reduced to lint/test gates or retired                             | Avoids maintaining two parallel deploy pipelines; Amplify connects natively to GitLab.com SaaS repos                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `ah-website-api` repo/host fate    | Archive the repo (read-only) and decommission its EC2 host after a soak period confirms the merged app is stable                                         | Keeps history for reference without carrying ongoing cost or maintenance burden                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Stripe SDK version                 | Use `stripe` ^23.0.0 in `ah-website-ui` (matches `ah-website-api`). `@stripe/stripe-js` stays where it is.                                               | With no `apiVersion` pinned the SDK sends its own pinned API version: v23.0.0 pins `2026-09-30.endive`, v17.7.0 pinned `2025-02-24.acacia`. Staying on v17 would change Stripe behavior vs. today's API. Newer `@stripe/stripe-js` releases removed `redirectToCheckout`, so that package is not bumped without switching to `session.url`                                                                                                                                                                                                                 |
| Stripe webhook                     | Drop. `stripe-webhooks` is not ported                                                                                                                    | Its only side effect was finalizing recurring invoices on `invoice.created`; Stripe finalizes them itself about an hour later, and the production endpoint has been disabled with no ill effect (checked in the Stripe Dashboard). The other branches only logged, and the product DB sync is gone. Dropping it removes a public POST route, raw-body signature handling and the `STRIPE_WEBHOOK_SECRET` secret. The endpoint dates from the June 2022 recurring-donations work. Delete the old staging and production endpoints in Stripe at decommission |
| `create-portal-session`            | Drop. Not ported                                                                                                                                         | Unauthenticated: it returned a billing portal URL for any email, and nothing in the UI calls it. Magic-link login + verify is the way into the portal                                                                                                                                                                                                                                                                                                                                                                                                      |
| Redirect URLs                      | Built from `CLIENT_BASE_URL`, not the request `Origin` header                                                                                            | `Origin` is client-supplied and was unvalidated (checkout `success_url`/`cancel_url`, portal `return_url`)                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Route tests                        | Tests ship with each route in WEB-22 (moved from WEB-24); Stripe and Resend are injected fakes, no network                                               | Follows Stripe's automated-testing guidance: mock Stripe in CI and use a sandbox for real behavior, sparingly. See `docs/stripe-testing.md`                                                                                                                                                                                                                                                                                                                                                                                                                |

## Current vs. Target Architecture

|             | Today                                                                                                               | Target                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Services    | Two repos, two EC2 hosts/containers: `ah-website-ui` (Next.js, port 3000) and `ah-website-api` (Express, port 3002) | One repo, one Amplify Hosting app                                                        |
| API surface | Express routes behind CORS, called via `NEXT_PUBLIC_API_BASE_URL`                                                   | Next.js Route Handlers under `app/api/*`, called via same-origin relative paths          |
| Data store  | Postgres (RDS) with one write-only table                                                                            | None — fully stateless, live Stripe API calls                                            |
| Auth        | Magic-link JWT → Stripe Billing Portal redirect (Express)                                                           | Identical flow, implemented as two Route Handlers                                        |
| Deploy      | GitLab CI → Docker Hub → SSH+Docker run on EC2, per app                                                             | Git push → Amplify Hosting build/deploy, per branch/environment                          |
| Env/secrets | Docker build ARGs (frontend) + `.env` file on host (backend)                                                        | Amplify Console environment variables, server secrets never exposed to the client bundle |

### [WEB-22] Port API routes into Next.js Route Handlers

Each route is a thin `route.ts` plus a `lib/handlers/<name>.ts` function, and **ships with its own route-level tests** (`*.integration.ts`, run with `yarn test:integration`) using injected fake Stripe and Resend clients. See `docs/stripe-testing.md`.

- [x] B1. `app/api/products/[type]/route.ts` (GET) — port `getProducts` (live Stripe product search by metadata). **Validate `:type` against an allow-list** before using it in the Stripe `products.search` query (the Express handler currently interpolates it unvalidated)
- [x] B2. `app/api/checkout/route.ts` (POST) — port `postCheckoutSession` (amount validation, price lookup/create, checkout session create). Return 403 when a recurring donation has no interval (matches the recent API fix; the old `return res.status(403)` never sent a response). New one-time donors are saved as Stripe customers (`customer_creation: always`), added in v2.8.1
- [x] B3. `app/api/checkout-sessions/[id]/route.ts` (GET) — port `getCheckoutSessionById`. A session id Stripe doesn't know returns 404 (v2.8.1), and an id Stripe cannot parse (for example one over 66 characters) returns 400 instead of a 500 that would land in Sentry (v2.8.3)
- [ ] B4. ~~`create-portal-session`~~ **Dropped.** The route was unauthenticated and nothing calls it; the portal is reached through login + verify (B5/B6)
- [x] B5. `app/api/login/route.ts` (POST) — port `loginHandler` + `sendMagicLink` (Resend email). The email is validated first; a Stripe failure returns 500 (Express was missing a `return` and crashed); Resend's `{ error }` result is checked so a failed send returns 500 instead of 204; the link is `${CLIENT_BASE_URL}/api/verify?token=`; the email's `environment` tag uses `NEXT_PUBLIC_APP_ENV` since `NODE_ENV` is `production` for both staging and production
- [x] B6. `app/api/verify/route.ts` (GET) — port `verifyMagicLink` (JWT verify → Stripe Billing Portal session → 302 redirect). The token is pinned to HS256 and must carry the login claims; an invalid, expired or tampered token returns 401 (Express hung); a deleted or missing customer returns 401 (Express sent nothing); other Stripe failures return 500; the portal `return_url` is `CLIENT_BASE_URL`
- [ ] B7. ~~`app/api/stripe-webhooks/route.ts`~~ **Dropped.** Its only effect was finalizing recurring invoices, which Stripe does on its own about an hour later, and the production endpoint is already disabled; the other branches only logged and the DB sync is gone. See the WEB-20 decision log
- [ ] B8. ~~`/health` and `/debug-sentry`~~ **Dropped.** `/health` only checked the database, and Amplify provides platform-level health monitoring; Sentry has its own verification tooling
- [ ] B9. ~~Remove the `cors` package/middleware~~ **N/A.** `cors` only exists in `ah-website-api`; all calls here are same-origin

## Risks & Mitigations

| Risk                                                                                            | Mitigation                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Amplify Hosting Next.js quirks (build size cap, response size cap, output mode) surface late    | Front-load the F5 spike before porting all 8 routes, not after                                                                                                                                      |
| Recurring invoices lose the webhook and rely on Stripe's automatic finalization (about an hour) | Verified in production, where the endpoint is already disabled. After cutover, confirm one renewal invoice finalizes and is collected (test clock in a sandbox first; see `docs/stripe-testing.md`) |
| Magic links already emailed point at the old API host and expire in 10 minutes                  | Don't cut over while one is outstanding                                                                                                                                                             |
| Stripe SDK / API version drift                                                                  | Port with `stripe` ^23 so the UI-hosted routes call the same API version as `ah-website-api` today; complete the Stripe test-mode pass (recurring checkout, portal login) before cutover            |
| `JWT_SECRET` mismatch breaks all in-flight (already-sent, unclicked) magic links                | Copy the exact current secret value into Amplify env vars rather than regenerating it                                                                                                               |
| Big-bang cutover has no incremental fallback if something's wrong                               | Route-level integration tests (WEB-24) before cutover, plus a defined soak period (G4) with the old infra kept warm enough to repoint DNS back if needed                                            |
